## 一、类别锁（CI 强制的结构性守门）

「类别锁」= 把某类缺陷的**整个失败面**变成一个测试：不是锁某个具体值，而是锁
「这类错误从此不可能静默发生」。每把锁都必须**变异验证**（临时注入该类错误 →
测试失败 → 还原全过），未变异验证的锁视为虚假锁定。

| 锁 | 测试类 | 锁什么 | 源轮 | 变异验证 |
|---|---|---|---|---|
| 流名集合+调用点计数 | `RngStreamInventoryTest` | `stream("X")` 字面量集合 = REF 36+xray 白名单；streamUse/streamPack/streamRound 调用点精确计数（同名新增调用点=双重消耗即失败） | R106/R146 | ✓（多余 shuffle 调用） |
| 小丑 key 引用存活 | `JokerKeyReferenceTest` | 源码全部 `findJoker("X")`/`key().equals("X")` 字面量 ∈ 150 注册表（拼写错=静默死引用） | R143 | ✓（chicotX） |
| desc 引用实名 | `DescNameReferenceTest` | 标签/挑战 desc 中每个「」token ∈ 命名全集（小丑/券/包/塔罗/星球/幻灵/Boss/牌组显示名） | R141 | ✓（乘公交） |
| Boss desc 倍率语义 | `BossDescMultiplierConsistencyTest` | desc 的「×N」与 blindTarget 实测倍率双向一致 | R139 | ✓（desc 改回 ×3） |
| 牌型歧义优先级 | `HandPrecedenceOrderTest` | 共满足手判定 = 高 order 型（链序=order 序双锁） | R144 | ✓（FLUSH 前移） |
| 多会话交错确定性 | `MultiSessionInterleaveTest` | 3 会话同线程交错 vs 独跑逐 tick 摘要一致（任何静态可变状态泄漏即分岔） | R138 | ✓（HandEval cnt 不清零） |
| 崩溃撕裂自愈 | `ServiceCrashTornFileTest` | FileStats 无换行尾行归一化后新追加不与残行拼接（追加式文件的断电窗口） | R140 | ✓（摘除自愈） |
| 分页帮助覆盖 | `BalatroHelpCommandTest#paginatedHelpCovers…` | 分页帮助必含全部 15 牌组 + 20 挑战 key（内容改动漏更帮助即失败） | R147 | ✓（隐去 monolith） |
| 基准场景文档同步 | `BenchScenarioDocConsistencyTest` | Scenarios.java 每个场景名 ∈ benchmark/README 场景表 | R148 | 首跑即抓 createRun 真漏项 |
| plugin.yml/usage 声明 | `PluginYmlConsistencyTest` | usage 与 SUBS 双向精确集合 + 元数据锁 | R107（前役） | ✓ |
| R137 修复守门 | `HandSizePermanenceTest`/`HexAnkhGrosDeadTest`/`ScoreContextGrantPoolTest` + `EndlessLongRunInvariantTest` 扩展 | handSizePerm 跨回合精确公式 / grosDead 单调+解锁 / 产出池口径（长局行为锁定） | R137/R145 | ✓（摘除 perm 叠加） |

## 二、不变量（代码评审时提取并全行核验）

1. **命中盒宽 ≤ 行内间距**（R150）：全息布局每行的命中盒宽不得超过行内间距
  （相邻盒可相切不可重叠）——新增/调整任何行布局时逐行验证。
2. **行间分离**（R150）：相邻行命中盒区间不相交；回合视图手牌↔消耗品行已知
   结构性重叠（行距 0.78 < 牌高 1.10）→ 实机清单第 18 项跟踪。
3. **流名四层**（R146）：名字集合（=REF+xray）∪ 动态名拼接次序 ∪ 调用点计数 ∪
   行为等价（黄金/sinkΔ/交错）——改任何流相关代码四层都要过。
4. **数值三处同步**（R126/R139 教训）：代码 / golden data.txt / desc 字符串——
   数值对齐必须三处同改，desc 侧无锁的域要加语义锁（如 BossDescMultiplier）。
5. **flags 生态双向**（R143）：每个被消费的 flag key 必须有发射者；发射者无
   消费者=死效果（chicot flag 为已知的无害冗余例外）。
6. **池化缓冲不逃逸**（R137）：acquire/release 严格 try/finally 嵌套；缓冲
   不得被外部持有后复用改写。
7. **静态池不可变**（R137）：跨会话共享的静态集合必须 `List.of`/`List.copyOf`
   或等价不可变；shuffle/sort 只落会话私有列表。
8. **卡守恒真形**（R158/R187）：三堆 ∪ 已入组未发 ≡ 牌组。「已入组未发」有三个
   来源：选包 playing 牌（R158）、商店买 playing 牌（R189 补覆盖）与大理石小丑的
   onBlindStart 加牌（R187——startRound 先洗牌后触发钩子，带大理石的回合恒有
   marbleCount 张 pending）。严格式「三堆≡牌组」仅在无这三源的闭包成立。
   守恒模板四变体：卡/钱/槽独立 + 跨维联合。
9. **可变集合写面普查**（R188-R193 五域收官）：RunState 全部可变游戏集合的写位点
   清单闭合——卡加侧 8 调用点（3 pending 源 + 5 即时入堆）、卡移除侧一规范入口
  （removeCardFromDeck 四表同删，上游玻璃破碎+destroyCard；其余直删全为堆间搬移）、
   钱（gainMoney 饱和通道 ×18 + 直接写 14 处全合法）、小丑（加 4 入口带槽位检查+flags
   重算 / 移 4 入口带 grosDead+钩子语义）、消耗品（addConsumableKey 规范 + perkeo
   自洽直写 / use+sell 移除）；tags/vouchers 为 append-only。**新改动触碰任一集合时
   对照本清单核对是否走规范入口**。

## 四、复用指南

- **任何引擎/数据改动**：跑全量测试（类别锁自动拦截大部分结构回归）；触及
  数值/文案时对照「三处同步」；触及流时对照「流名四层」。
- **任何性能批次**：合入后跑一轮「数据安全镜头」五面（见 R137 章）。
- **新审计轮**：优先选有**可构造失败模式**的面（本文档三的镜头库），零缺陷
  预期时产出类别锁或长局锁作为轮次资产。
- **新守门测试**：必须变异验证后才能视为有效锁；优先类别锁（锁整类错误）
  而非点锁（锁单个值——点锁交给黄金用例）。
