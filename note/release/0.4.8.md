## 服务层审计结论（留档，确认安全）

- **FileStats**（stats.txt）：内存/文件双有界（MAX=10000，超出丢最旧）；追加每满 MAX 触发一次原子压缩（tmp+move，防半文件）；启动流式读尾 deque（无内存尖峰），超限一次性 compact；decode 严格 7 段 + 种子长度/控制字符防御（脏行/部分写一律拒收）；`record`/`all` synchronized；目录仅确保一次（无高频 stat）。
- **FileWinCounter**（wins.txt）：每次 increment 原子重写（tmp+move，ATOMIC_MOVE 不支持时降级）；load 拒绝脏行/非正计数；条目数随**独立玩家数**增长（无上限——与 Minecraft usercache.json 同一平台惯例，非泄漏，留档说明）。
- **MemoryLeaderboard**：top/topAggregated 均先复制再排序（O(n log n)，n≤10k，/top 有 1s/人节流，主线程安全）；比较器各段独立（注释记录了 reversed 链陷阱）。
- **Services**：setStats/setWinCounter 同步重绑 MemoryLeaderboard（0.4.3 修复），onEnable 装配顺序（setStats→setLeaderboard→setWinCounter）验证安全。
- **VaultEconomy**：反射一次性解析四个方法、任一缺失整体不可用（不会半可用误报）；`has` 无 Vault 时仅 ≤0 返回 true（NoOp 语义）；`getOfflinePlayer` 走内存缓存无磁盘 IO；游戏流程不直接调用 economy()（纯第三方 API 面）。
- **MemoryStats**：synchronizedList + 同步块读写，有界 10000。
