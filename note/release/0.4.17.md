# Balatro v0.4.17 — GUI 种子等待取消修复 + Rng 边界契约回归

> 基线：Minecraft 1.21.11 / Paper API（Papo 服务端）。本轮深审会话/渲染/监听/GUI 集成层的
> 资源生命周期与交互一致性，修复一个真实交互逻辑缺陷，并补 Rng 算子边界回归。

## 修复

### GUI 种子等待未在重开菜单时取消（交互逻辑错误）

**现象**：`/balatro gui` → 确认页点「种子」→ 界面关闭、进入 60 秒聊天输入等待。若玩家在等待
期间**重新打开 GUI** 浏览菜单，再发一条普通聊天（本意与人交谈）：
1. 该聊天被 `pendingSeeds` 吞掉（`e.setCancelled(true)`，不广播）；
2. 玩家被强制弹到 CONFIRM 页，打断其当前菜单浏览。

玩家此时已离开种子输入上下文（界面关了、又重开了），完全没意识到这条聊天会被当成种子。

**根因**：玩家重开 GUI（回到菜单流程）时，其待处理的种子等待（`pendingSeeds`）未被取消，
系统仍把下一条聊天当种子。

**修复**：`GuiManager.openMenu` 入口取消该玩家的 pendingSeed——打开任何菜单即视为已回到 GUI
流程、离开种子输入上下文。

**无回归论证**：正常种子确认路径不受影响——`onChat` 已先 `pendingSeeds.remove(id)` 原子认领，
`handleSeedInput` 设置种子后重开 CONFIRM 页时，`openMenu` 内的 remove 为 no-op；
`promptSeed` 先 `put` 再 `closeInventoryLater`（关界面、不开菜单），同样不经过此 remove。

## 集成层确认（无缺陷，留档）

逐行核查会话/渲染/监听/GUI 全链路，以下均已正确：

- **SessionManager**：`putIfAbsent` 防开局重入、`endIfCurrent` 防事件监听器重开后误杀新局、
  `shutdownAll` 逐一回收实体、开局异常不入表。
- **SessionListener / BoardMoveListener**：离线清理；跨世界/远传/重生迁移（取消事件检查 +
  1 tick 延迟取新坐标 + 异常兜底）。
- **RoundBoard**：自愈递归保护（`selfHealing`）、relocate 保留选中、`ownsInteraction` 归属校验、
  `despawn` 清空全部实体/槽位列表。
- **BalatroPlugin**：5 个事件桥全 try/catch（第三方监听器异常不击穿游戏流程）、
  `sweepStaleBoards` 启动清扫残留实体、onDisable 先关 GUI 再收会话。
- **BoardListener**：归属确认即取消（含被节流的点击）、`parseIntSafe` 绝不抛异常、
  dispatch 全 try/catch（异常客户端输入不致踢出）。

## 新增测试（RngBoundaryTest ×13）

锁定 `Rng` 算子的边界契约（此前 golden 仅测正常值单点，边界漂移会引发静默逻辑错误）：

- `weighted`：空/null 列表、全零/全负权重 → null；唯一正权重恒被选中；负权重按 0 处理。
- `chance`：`≤0` 恒 false、`≥1` 恒 true（钳制语义，玻璃/幸运猫等概率牌依赖）。
- `range`：`range(x,x)` 恒返回 x；结果恒在含端点区间内。
- `pick`：空/null → null；单元素恒返回自身。
- **命名流独立性**：同种子不同流名产生不同序列；推进兄弟流不影响本流重放（种子复现基石）。
- `shuffle`：原地、是输入的排列（无增删）。
