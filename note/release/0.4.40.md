# Balatro v0.4.40 — 降低 Minecraft 版本需求（最低 1.21.11 → 1.19.4）

> 基线：v0.4.39（main，6174c6a）。分支 `lower-mc-version`，任务定义见
> [note/tasks/lower-mc-version.md](../tasks/lower-mc-version.md)。
> 用户约束：**不改变展示方式、不改变插件功能**，仅降低所需版本。

## 结论

最低支持版本从 **Minecraft 1.21.11** 降到 **1.19.4**（全息展示方式的引入版本，即硬下限），
上限不限（含 Papo 1.21.11）；Java 要求从 21 降到 **17**（1.19.4~1.20.4 服务端的要求，
更高版本服务端兼容 17 字节码）。展示方式（世界全息 TextDisplay/Interaction + 右键交互）、
全部功能（命令/全息/GUI/服务/API 扩展面）零变更。

## 方法：先清点、后动手

1. **API 面全量清点**（main 源码 import + 方法调用点）：版本敏感项只有
   `TextDisplay/Display/Interaction` 实体 + `Transformation(JOML)`（1.19.4）、
   `setVisibleByDefault/showEntity`（1.19.3）——其余全部 ≤1.17；
   未使用 `InventoryView`/`org.bukkit.inventory.MenuType`/`ServerBuildInfo`/1.20+ Material。
2. **编译锚定下限**：`compileOnly` 换 `paper-api:1.19.4-R0.1-SNAPSHOT`，
   编译期只见 1.19.4 的 API 面，从源头杜绝误用更新 API。编译暴露**唯一**超出项：
   `ItemMeta#setEnchantmentGlintOverride`（1.20.5+ 组件改版 API）。
3. **字节码降 17**：源码无 Java 21 专属 API（唯一 `.reversed()` 是 `Comparator` 的 Java 8 方法），
   `--release 21` → `--release 17`（产物 major 61 已核）。

| `PluginYmlConsistencyTest` | api-version 构建期锁同步 `'1.19'` |

## 验证

- **单元测试**：`./gradlew build` **458 全过**（0 失败 0 错误，与 0.4.39 持平）；
  产物 `balatro-0.4.40.jar`，class 字节码 major 61（Java 17）。
- **上限端无头启动**（Papo bundler 1.21.11 + Java 21，沿用 R84 验证模式）：
  `Loading → Enabling → Balatro v0.4.40 enabled. → Done (15.153s)`，零异常零堆栈。
  spigot-mapped 产物在 mojmap 运行时经 Paper PluginRemapper 自动重映射（218ms）——
  正是老编译插件跑新服务端的标准兼容机制。
- **下限端无头启动**（Paper 1.19.4 build 550 + Java 21）：直接加载启用零异常，`Done (6.086s)`。
  （本机无 Java 17，故下限端跑在 21 上；17 字节码在 17+ JVM 均可加载，无风险。）
  环境备注：1.19.4 paperclip 首跑需下载原版 jar，本机 Java TLS 被网络拦截，
  已用 curl 预取 piston-data 官方 jar 放入 `cache/mojang_1.19.4.jar` 绕过。
