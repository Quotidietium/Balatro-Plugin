# Balatro v0.3.9 — voucher 标签生效 + 无尽排行榜改造 + 审计轮次 13-14

> 0.3.8 的审计修复 + 功能补全版。基线：Minecraft 1.21.11 / Paper API（Papo 服务端）。
> 经 14 轮逐项审计（详见 [稳定性审计.md](稳定性审计.md)），发现并修复多处缺陷，
> 实现两处此前待拍板的产品决策。

## 一、功能补全（两处待拍板项）

### 1. voucher 标签生效——追加额外券到下个商店（对齐真版）

真版 Balatro 的 Voucher Tag 效果为「Adds a Voucher to the next Shop. Can be stacked」
（[Voucher Tag Wiki](https://balatrowiki.org/w/Voucher_Tag)）。REF 原版网页
（`engine.js:226`）与此前 Java 均只置位 `extraVoucher` 而不消费——标签完全无效。

- `ShopData.voucher`（单券）→ `vouchers`（`List<VoucherItem>`），支持多张。
- `Engine.gainTag` 的 voucher 标签从 `put(true)` 改为 `merge` 计数器（支持叠加）。
- `Shop.genShop` 按 `extraVoucher` 计数从可用券池追加额外券（不重复，可用券不足则少几张）。
- `Shop.buyVoucher(idx)`、`GameSession.buyVoucher(idx)` 带序号。
- 渲染层 `voucherSlots` 循环、`voucher:i` 命中盒；命令层 `cmdBuyVoucher` 单券时允许省略序号。
- 联网核实来源：[Voucher Tag – Balatro Wiki](https://balatrowiki.org/w/Voucher_Tag)、
  [Tags – Fandom](https://balatrogame.fandom.com/wiki/Tags)。

### 2. 无尽排行榜改造——按玩家聚合 + 三级排序

此前排行榜为单局记录列表（通关 ante8 后进无尽、于无尽死亡会再记一条「失败 底注N」，
与「通关 底注8」并存，语义矛盾）。改为按玩家聚合：

- 每玩家一行：**最高到达底注（含无尽 ante 9+）** + **累计通关次数**。
- 排序：bestAnte 降序 → winCount 降序 → 玩家名称升序（相同时并列）。
- 新增 `PlayerStat` 记录、`WinCounter` 接口 + `FileWinCounter` 持久化（`wins.txt`）。
- `LeaderboardProvider.topAggregated(n)`（带 default 实现向后兼容）。
- 无尽死亡记录照常记 stats——其 ante 贡献给 bestAnte（显示为「无尽N」而非「失败」）。

## 二、审计修复（轮次 13-14）

### 3. 补充包 standard 牌版本分布错误（移植错误，轮次 14）

`Packs.genPackCard` 的 STANDARD 牌版本原用 `weightedEdition`（50/35/15 加权），
但 REF `engine.js:1433` 为 `s.pick(["foil","holo","poly"])` **均匀 1/3**。分布错误
且破坏种子复现。改为 `eds[range(0,2)]` 均匀。新增 `PacksEditionParityTest`（400 种子统计）。

### 4. 单局排行榜 Comparator 链 bug（轮次 14 发现的长期 bug）

`MemoryLeaderboard.RANK` 的 `.comparing(won).reversed().thenComparingInt(ante).reversed()`
——第二个 `.reversed()` 反转**整个** comparator（含前段），导致 won 变升序
（**失败的排在通关的前面**）。改为 `.thenComparing(子comparator)` 确保各段独立降序。
经独立 Java 程序验证修复前后排序行为。`topAggregated` 同样修法。

### 5. Shop.weightedPick NPE 防御（轮次 14）

`st.weighted(weights, ...)[0]` 若 `weighted` 返回 null（空列表/全权重≤0）则 NPE。
当前 `genShopCards` 保证非空不可达，但作为防御性兜底加 null 检查。

### 6. BalatroCommand 命令层异常兜底（轮次 13）

`onCommand` 无统一 try/catch。第三方事件监听器或意外引擎状态抛 RuntimeException 会
逃逸到 Bukkit 命令分发器。改为外层 try/catch → 记日志 + 友好提示。

### 7. 资源解析健壮性（轮次 13）

`JokerRegistry.loadMeta`/`ChallengeMods.load`/`applyOne` 的解析仅捕获 IOException，
未捕获 RuntimeException。改为捕获 RuntimeException（单行/单条非法跳过，不阻断加载/开局）。

## 三、审计核验结论（无修改）

轮次 13-14 覆盖：命令层异常路径、全息渲染层、资源加载、会话生命周期、服务层、
**全 150 小丑钩子的并发快照安全**（onScore/onScoreCard/onHeld/onPlayHand/onDiscard/
onRoundEnd/onSkip/onBossDefeated/onGlassBreak/onFaceDestroyed/onSell/onAnySell 均用快照
副本或 `contains` 防御，评分循环基于独立 `activeJokers` 副本）、Shop/Packs 极端种子边界
（空池/越界/重掷全自检）。逐项通过。
