# Balatro v0.3.6 — 安全加固 + 长期稳定性 + 逻辑缺陷修复

> 0.3.5 的全面审计修复版。基线：Minecraft 1.21.11 / Paper API（Papo 服务端）。
> 目标场景：**长时间高负载、多用户高频率使用**；客户端输入一律视为不可信。

## 一、安全加固（客户端输入不可信）

### 1. 全息交互实体归属校验

牌桌实体虽为本人私有可见，但客户端可被篡改、实体 id 可被枚举探测（服务端对
`INTERACT` 包仅校验距离）。篡改客户端可对任意实体 id 发交互包，点到**他人牌桌**
的命中盒或伪造 `balatro_i_*` 标签的实体。

- `RoundBoard.ownsInteraction(entity)`：交互派发前确认命中盒确属本人本牌桌，否则拒绝。
- `BoardListener.dispatch` 外包 try/catch：任何异常都不向事件/网络层逃逸（防异常输入
  触发踢出/报错），仅记日志。
- 命中盒动作参数全部经宽松解析（`parseIntSafe`：非数字/超长一律拒绝，绝不抛出）。

### 2. 种子输入校验

种子来自客户端，原先不做任何限制：超长种子会进入 RNG 哈希、统计文件、聊天展示，
含 `|` 的种子还会**破坏统计文件行格式**（数据操作 BUG）。

- `Rng.isValidSeed`：长度 1~32，仅字母/数字/`_`/`-`；命令层先行校验并提示，
  `SessionManager.start` 兜底拒绝（记日志）。
- `FileStats.decode` 同步加固：严格 7 段、拒绝控制字符与超长种子，脏行丢弃不入库。

### 3. 命令参数健壮性

- `play` 的牌组/挑战参数**规范化为表内规范 key**（原先大小写不敏感匹配后原样传入，
  引擎按 key 大小写敏感处理 → `/balatro play RED` 直接崩溃、`OMELETTE` 静默丢失挑战修饰）。
- `use` 的手牌序号解析补 try/catch（原先非法输入直接内部报错）。
- `promptBlindSelect` 对空 `bossQueue` 防御（原先 `Boss.byKey("")` 会抛异常）。

## 二、长期稳定性（高负载/长时运行）

### 4. 跨世界/远距离传送/重生 → 牌桌迁移（新增 BoardMoveListener）

牌桌实体锚定世界坐标。原先玩家跨世界（下界门/末地门/传送指令）后牌桌留在旧世界，
会话卡死在"有局无桌"；死亡重生/远距离传送后牌桌留在原地无法回去。

- 新监听器：跨世界或同世界 >64 格传送、玩家重生 → 下一 tick 在玩家眼前重建牌桌
  （`RoundBoard.relocate`，保留局面与选中牌）。
- `RoundBoard` 世界引用改为生成/迁移时锁定（原先实时取玩家当前世界，跨世界后会
  把新实体混放进旧世界坐标）。
- 自愈：刷新时若核心实体已失效（区块卸载移除非持久实体）→ 自动在玩家眼前重建。

### 5. 插件关停/重载回收牌桌

`SessionManager.shutdownAll` 原先只 clear map **不销毁实体**，插件 disable/reload 后
世界内残留整套全息。现逐一 `despawnBoard`（个别清理失败不阻塞关停）。

### 6. 节流表泄漏

`BoardListener.lastClick` 原先只增不减（玩家离线不清理），长期运行无限增长。
现监听 `PlayerQuitEvent` 即移除。

### 7. 统计文件/排行榜有界化

`FileStats` 原先内存与文件**无限增长**：`top()` 每次在主线程复制+全量排序，
长时运行后成为卡顿源，启动加载也越来越慢。

- 上限 10000 条（只保留最近记录，排行榜语义即"最近最佳"）；运行期内存恒定有界。
- 启动加载检测超限 → 一次性压缩重写文件，文件不再无限膨胀。
- IO 失败记日志（原先静默吞掉）。
- `MemoryLeaderboard.top(n)` 对 `n<=0` 防御（原先会抛 `IllegalArgumentException`）。

## 三、逻辑缺陷修复

### 8. 8 号球小丑效果缺失（对照原版 engine.js）

`ScoreContext.gainConsumable` 是空 TODO 桩 → **EIGHTBALL（8 号球）计分发塔罗的效果
完全不生效**。按原版实现补齐（consumable 流取牌 + 成功记事件），并补
`RunState.gainConsumable` 的"获得：名称"消息对齐。

### 9. 浮雕牌组(anaglyph)击败 Boss 无翻倍标签

`Engine.endRound` boss 分支原注释"→ 0.5.0"未实现；原版在击败 Boss 时
`gainTag(state, "double")`。补齐（新增专项回归测试）。

### 10. 出售后消耗品行不刷新

`/balatro sellc` 成功后全息不更新（`sellJoker` 有、`sellConsumable` 漏）。补齐。

### 11. HandScore 事件时序

被引擎拒绝的出牌（非法选牌/Boss 限制）原先也发 `BalatroHandScoreEvent(score=0)`，
第三方监听者会误记为一次计分。改为仅实际计分（`r.ok`）时发出。

### 12. 陈旧选中的牌

消耗品销毁/改写手牌后，`RoundBoard.selected` 残留已不存在的卡 id：
"选中 N" 计数虚高、出牌混入无效 id。现 `update` 时剪除不在手牌中的选中 id；
`toggleSelect` 同时拒绝不在手牌中的 id。

### 13. 全息交互无失败反馈

原先右键购买/重掷/选择失败（资金不足/槽满/已售）只播音效无任何提示；
出牌/弃牌被 Boss 规则拒绝（如翠绿铃必须含指定牌）也静默清选中。
现均在聊天框给出原因。

### 14. 黄昏/杂技演员「最后一手」永不触发（审计 #8/#9，原版 bug）

计分发生在 `handsLeft--` 之前，最后一手计分时 `handsLeft==1`；原版网页
dusk/acrobat 判 `==0` → **两个小丑完全无效**。按真实 Balatro 规则改判 `==1`，
并同步修正黄金值（仅 acrobat 场景最后一手 15→45，联网核实规则
[Wiki](https://balatrowiki.org/w/Dusk) / [Fandom](https://balatrogame.fandom.com/wiki/Acrobat)）。
新增 JokerFinaleTest×4 回归。

### 15. 礼品卡漏加消耗品售价（审计 #10，移植遗漏）

原版 giftcard 回合结束给**小丑与消耗品**售价各 +$1，Java 移植只加了小丑。补齐。

### 16. gainRandomJoker 流名与算法错误（审计 #11，种子破坏级）

审判/灵魂/幽灵/补充标签/杂牌军都经 `gainRandomJoker`。原实现：
① 误用 `jokergrant` 流（原版 `randomjoker`）；② 未指定稀有度时原版从
普通+罕见+稀有混合池均匀抽取，误为 70/25/5 分段掷骰（分布错误且多耗随机）；
③ 原版满槽先返回不耗流，误为先抽后查槽。全部对齐原版。

### 17. gainJoker 未重算 flags（审计 #12）

原版 gainJoker 加入后立即 computeFlags；Java 遗漏 → 回合中经「审判」等获得
带 flags 的小丑（fourFingers/splash/handSize 等）不生效。补齐。

### 18. 星座/全息影像累积钩子缺失（审计 #13/#14，完全失效）

三方全量钩子审计（150 小丑逐项对照 jokers.js）发现：
- **constellation（星座）** 漏 `onUsePlanet`（每用星球牌 +0.1x）→ 恒 ×1.0；
- **hologram（全息影像）** 漏 `onCardAdded`（每加入游戏牌 +0.25x）→ 恒 ×1.0。
均已补齐并加 JokerAccumulateTest×2 回归。
同批审计确认：其余 148 小丑钩子挂载/数值/流名/extra 字段与原版一致；
ridebus 重置逻辑经人工复核正确（自动审计误报已排除）。

### 20. 命运之轮/光环版本分布错误（审计 #15/#16，概率改写）

原版对版本做 `pick(["foil","holo","poly"])` **均匀 1/3** 抽取；Java 误用商店
权重 50/35/15（把 Data.Edition.chance 当成了抽取权重）→ 概率语义错误且同种子
结果分歧。两处均改回均匀抽取（ConsumableParityTest 300 种子分布回归锁定）。

### 21. trimHand 阈值缺 +3（审计 #17，效果作废级）

原版允许手牌临时溢出至 `handSizeRound+3`；Java 按上限硬裁剪 → **满手时
cryptid（地穴生物）的 2 张复制直接进弃牌堆（效果基本作废）**，familiar 等
生成的牌也被丢弃。阈值对齐原版。

### 22. 销毁手牌后缺补牌（审计 #18）

原版 `destroyRandomHandCards` 销毁循环后 `drawUpTo`；Java 缺失 → immolate（献祭）
后手牌停留在上限-5；wheel Boss 回合还跳过 wheel 流消耗造成后续流分歧。补齐。

### 23. destroyCard 尊重 allFace（审计 #19）

空想性错觉（pareidolia）在场时所有牌视为人头牌；Java 销毁钩子硬编码
rank 11-13 → 销毁非人头牌不触发 onFaceDestroyed（canio 不累积）。改用 `isFace`。

### 24. 大理石小丑石头牌壳（审计 #20）

原版 marble 生成的石头牌为**黑桃 2 壳**（`makeCard(2,0)` 默认值副作用）；
Java 用 0/-1 壳 → 吸血鬼剥掉石头增强后变 rank=0 异常牌（原版复原为 2♠）、
邮寄返利目标 2 时永不匹配。对齐原版壳；牌组构建的石头牌仍为 0/-1 壳（同原版
两处约定）。联网核实真实规则：石头牌有隐藏壳，增强移除后复原
（[Stone cards](https://balatrowiki.org/w/Stone_cards) / [Vampire](https://balatrogame.fandom.com/wiki/Vampire)）。

### 25. 三方交叉审计结论（逻辑闭合）

- 150 小丑（a-g 62 / h-z 88）逐项对照 jokers.js：钩子集合 0 缺失 0 多余，
  数值/流名/extra 字段一致（除上述已修项）。
- 52 消耗品（塔罗22/星球12/幻灵18）逐项对照 engine.js：目标数量/流名构造/
  愚人防护/生成池/小丑操作/复制方向一致（除上述已修项）。
- 有意保留的两处差异（消耗品后自动整理手牌 = 0.2.0 决策；gainJoker 提示消息 = UX）
  已记录于 [逻辑审计.md](逻辑审计.md)「有意保留」表。
