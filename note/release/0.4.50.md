# Balatro v0.4.50 — P12 性能优化：商店池物化消灭（负结果轮）

> 基线：Minecraft 1.21.11 / Paper API（Papo 服务端）。性能战役第三期第 1 轮。

## 改动

1. **（实验后回退）商店/发放路径两趟虚拟抽取**：makeJokerItem/genShop 券池/gainRandomJoker
   改为「计数 → `(int)(next()*n)` → 取第 n 个匹配」的零分配抽取（等价性有差分守门测试）。
   best-of-3 交替顺序交错 A/B 证明：分配 shopGen −19.8%（三对逐位一致）但**时间 0.838×
   完全分离回归**——第二趟 105 元素过滤 ~0.25μs/次 vs TLAB 物化 490B ~50ns，净亏 4 倍。
   按红线以时间为准回退；负结果注释留代码原位。
2. **（保留）`RunState.gainConsumable` 静态池共享**：无禁入时塔罗直接用 `Data.TAROTS`、
   幻灵用静态 `SPECTRAL_GRANT_POOL`（与物化过滤池同内容同序），每次调用省 ~190~250B，
   零额外遍历严格胜出；有禁入回落原物化路径。
3. **（保留）`Engine.FACE_RANKS` 静态常量**：numbersToFaces 挑战构局 52 次 `List.of` → 0。
4. 新增 `VirtualPickEquivalenceTest` 差分等价守门（3 用例：gainConsumable 双轨对照 ×2 +
   构局确定性），463 测试全过。

## 方法论资产（TLAB 结论第三次扩展）

「小列表**物化**不敌 TLAB」（P10 快照池中性、P11 商店池 +4% 回退）扩展为：
**任何额外遍历（两趟虚拟抽取）也不敌 TLAB 新鲜分配**——分配削减 ≠ 时间收益，
百元素级列表物化 ~0.1ns/B，替代方案必须先赢过这笔账。
