## 审计确认安全的路径（留档）

### API 事件类（5 个）——不可变 + 主线程同步

- **字段全 final**：RunStart/HandScore/BlindResult/AnteClear/RunEnd 的字段均为 UUID/String/long/int/boolean
  不可变类型；无 setter（除 RunStart.setCancelled）；无暴露内部可变集合——监听器**无法篡改**事件字段。
- **同步事件**：5 类均未调 `super(true)`（async），为同步事件；fire* 经 `PluginManager.callEvent` 同步派发，
  监听器在主线程运行——与 API.md「事件在主线程同步发出」一致。
- **仅 RunStart 可取消**：fireRunStart 检查 isCancelled（R7 加 try/catch 隔离）；其余 4 类不可取消。
- **HandlerList 规范**：5 类均有 `getHandlers()` 实例方法 + `getHandlerList()` 静态方法（Bukkit 约定）。

### 服务接口契约（5 个）——边界清晰

- **EconomyService**：balance/has/deposit/withdraw，契约注明「withdraw 调用方应先 has」。
  金额符号无约束，但插件游戏流程**从不直接调 economy()**（纯第三方 API 面，R8 确认），故负值风险仅限第三方调用方。
- **StatsService / LeaderboardProvider / RewardService / WinCounter**：契约清晰；LeaderboardProvider.topAggregated
  为 default 方法（旧实现返回空不破坏）。
- **数据载体不可变**：RunSummary、PlayerStat 均为 Java `record`（天然 final 字段、无 setter）。

### 持久化文件抗篡改

- **FileStats.decode**：严格 7 段 split + UUID/Int/Long/Boolean 解析全 try-catch（脏行返回 null 丢弃）+
  种子长度≤64 + 无控制字符——篡改的 stats.txt 无法崩插件。
- **FileWinCounter.load**：split + UUID/Int 解析 try-catch + `c > 0` 过滤——脏行/负计数丢弃。

### 文档最终一致性

- **README 命令清单** vs `BalatroCommand.dispatch`：全一致（含 8 组别名 gui/menu、status/hand、
  playcard/pc、disc/discard、buybag/pack、buyvoucher/voucher、cons/consumables、help/?）；`cancel`
  故意不文档化（全息确认按钮回执，非玩法命令）。
- **plugin.yml usage** 覆盖全（除 cancel）。
- **无陈旧版本引用**：README 仅含当前 0.4.12 jar；API.md 版本中性（0.3.9 等为历史标记）。
