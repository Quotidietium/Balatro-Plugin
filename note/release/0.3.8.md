# Balatro v0.3.8 — 稳定性与安全审计修复

> 0.3.7 的持续审计修复版。基线：Minecraft 1.21.11 / Paper API（Papo 服务端）。
> 经 12 轮逐项审计（详见 [稳定性审计.md](稳定性审计.md)）发现并修复 4 处稳定性/逻辑缺陷。

## 一、稳定性修复

### 1. FileStats 长期运行稳定性（流式有界加载 + 运行期压缩）

`FileStats.load` 原用 `Files.readAllLines` 把整个统计文件读入内存；文件仅在启动加载时压缩，
长时高负载不重启可膨胀至数十万行，下次启动读取造成**内存尖峰与启动变慢**。

- 改为**流式读取**，内存中只保留最近 `MAX_RECORDS`(10000) 条（不再一次性读入整个文件）。
- 新增**运行期压缩**：每累计 `MAX_RECORDS` 次追加触发一次 `compact`，把文件收敛回当前内存（≤上限），
  避免数周不重启时文件无限膨胀。
- `createDirectories` 改为仅首次写入执行一次（去除高频写入下的无谓 stat）。

### 2. VaultEconomy 可用性判定（反射初始化健壮性）

`VaultEconomy` 构造原在 `getProvider` 后即赋 `econ`，4 个反射方法（getBalance/has/deposit/withdraw）
在其后解析；若某 `getMethod` 抛异常（非标准 Economy 实现），`econ` 仍非空而方法为 null →
`available()` **误报 true**、调用处静默空操作（try/catch 兜底不崩但失真）。

- 改为**先解析全部方法，四个都成功才** `econ = provider`；任一失败则 `econ = null`，
  `available()` 如实返回 false，回退 `NoOpEconomy`。

## 二、逻辑修复

### 3. 四指(Four Fingers)同花顺/皇家：异花牌不计分（联网核实）

四指下打出「4 同花 + 1 异花」凑出的同花顺/皇家，原计分用 `addAll(suited)`，**把异花的第 5 张牌
也算进计分牌**（虚高分）。

- 同花顺/皇家改在**同花牌集 `flushCards` 内**重判顺子；计分牌仅取同花色牌（异花牌不计分）。
- 皇家判定改「同花顺窗口内所有点数 ≥10」（四指下 K-Q-J-10 同花即皇家，不要求 A）——此前误判需含 A。
- 联网核实真版规则：皇家即「全 ≥10 的同花顺」；四指下顺/同花/同花顺/皇家均降至 4 张。
  来源：[Four Fingers](https://balatrogame.fandom.com/wiki/Four_Fingers)、
  [Poker Hands](https://balatrogame.fandom.com/wiki/Poker_Hands)。
- **非四指完全不变**（非四指同花时 `flushCards == suited`），`EvalGoldenTest` 与既有黄金用例无回归。

### 4. cmdUse 边界一致性

`/balatro use` 消耗品序号原手写解析，是唯一未走 `parseOne`、缺 `<0` 越界拦截的序号命令
（越界仅靠 `Consumables.use` 兜底，报错文案也逊于其它命令）。改为统一经 `parseOne`
（1-based→0-based + 越界/非数字统一拦截），与 buy/pick/sellj/sellc 一致——契合
「不信任用户输入，在边界处校验」。

Packs / Card / Joker 全套 / ScoreContext / PlayHandInfo / Phase / Mods / StreamSource / Decks /
