# Balatro v0.4.18 — 命令层序号解析溢出加固

> 基线：Minecraft 1.21.11 / Paper API（Papo 服务端）。本轮深审 `/balatro` 命令层的不可信输入边界，
> 修复一处整数溢出隐患。**结论：命令层全部入口越界安全，无数据危害路径**。

## 修复

### parseOne 序号解析整数溢出（MIN_VALUE 回绕绕过检查）

**现象**：`parseOne` 原实现 `Integer.parseInt(args[1]) - 1`。输入 `-2147483648`（Integer.MIN_VALUE）
时，`-1` 操作溢出回绕为正数 `2147483647`，绕过命令层的 `if (idx < 0) return;` 拦截。

**实际危害**：**无数据错误**——下游引擎层 `buyCard`/`buyPack`/`buyVoucher`/`sellJoker`/`sellConsumable`
对越界 idx 一律 `idx < 0 || idx >= size` 返回 false 兜底。但「不信任用户输入」原则下，命令层应自行
正确拦截，不应依赖下游接住。

**修复**：改用 `Long.parseLong` 解析，显式校验 `1..Integer.MAX_VALUE` 后才转 int 减 1。
`0` / 负数 / `MIN_VALUE` / 超 int 值（如 `2147483648`、`999999999999`）全部正确返回 -1 拦截。

**不影响**：`parseIndices`（playcard/disc）与 use 的手牌序号用 `Integer.parseInt` + `idx<1||idx>size`
拦截，`Integer.MAX_VALUE - 1` 不溢出、超 int 值 parseInt 直接抛异常被 catch——无同类缺陷。

## 命令层确认（无缺陷，留档）

逐行核查 `BalatroCommand`（801 行）全部子命令：

- **权限实施**：onCommand + onTabComplete 双双拦截 `balatro.play`（无权限不补全、不暴露命令结构）。
- **统一兜底**：onCommand 顶层 try/catch RuntimeException（第三方事件监听器异常经 GameSession
  间接抛出也不击穿命令分发器）。
- **开局参数识别**：`cmdPlay` 顺序不限自动识别 赌注数字/牌组名/挑战名/种子；种子经 `Rng.isValidSeed`
  校验（长度/字符集）。
- **序号越界双保险**：命令层 parseOne/parseIndices + 引擎层 `buyCard`/`sellJoker` 等均 `idx<0||>=size`。
- **错位校验**：use 的 `kind:key`、sellj 的 `key`——确认按钮点击前列表已变则取消（防错位误操作）。
- **cmdTop 节流**：每玩家 1s + lastTop 惰性清扫（>128 且 >60s 失效）+ `topAggregated` 异常降级。
