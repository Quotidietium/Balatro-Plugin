# Balatro v0.4.1 — 开局向导 GUI 安全加固（并发/同步开关/节流）

> 基线：Minecraft 1.21.11 / Paper API（Papo 服务端）。在 0.4.0 基础上修复开局向导 GUI
> （`gui` 包，0.4.0 新增、此前 60 轮审计未覆盖）的三项安全/稳定性缺陷。
> 纯修复版本：无新功能、无 API 变化，存档/统计格式不变，完全向后兼容。

## 修复清单

| # | 问题 | 修复 | 严重性 |
|---|---|---|---|
| 1 | `GuiManager.pendingSeeds` 为普通 `HashMap`，却被异步线程（`AsyncChatEvent.onChat` 的 get/remove）与主线程（put/remove/clear）并发访问：无 happens-before 保证，主线程 put 触发 resize 时异步线程可观察到不一致桶表；且 get-then-remove 非原子，同一玩家快速连发两条聊天会被双重吞并、双重设置种子、双重弹窗 | 改 `ConcurrentHashMap`；`onChat` 以原子 `remove(id)` 一次性认领等待条目（顺带修复双重处理竞态） | 并发数据操作缺陷 |
| 2 | `InventoryClickEvent` 处理器内同步调用 `openInventory`（openMenu）与 `closeInventory` 共 8 处，违反项目既定约束（`note/references/papo-服务端.md` §3：处理器内不同步开/关界面，须下一 tick），可致客户端幽灵物品与包序错乱 | 新增 `openMenuLater`/`closeInventoryLater`，点击路径的界面开/关统一延后 1 tick；选择状态（GuiState）点击当下同步修改不受影响；开局参数点击时捕获为不可变 `StartRequest`，开局整体延后 1 tick 保持「先关界面、后开局」顺序 | 稳定性 |
| 3 | GUI 点击无节流：篡改客户端可高速刷点击包，每次选择点击都重建 27/54 格界面（数十个 ItemStack/Component 分配 + 发包），多玩家高频下放大为主线程 TPS 压力 | 每玩家 150ms 点击节流（对齐 `BoardListener` 既有约定），quit/closeAll 清理节流表；物品保护性 `setCancelled(true)` 不受节流影响 | 高负载稳定性（DoS 面） |

## 未改动（复核确认安全）

- `onClick` 的 `e.getSlot()` 只做整数比较与 `GuiLayout.indexOfSlot`（任意 int 安全返回 -1），无数组索引 → 篡改客户端发送越界槽位无 OOB 风险。
- 玩家背包侧点击/拖拽一律取消（防物品偷入/取出）的策略不变，且不受节流影响。
- 种子校验链：`Rng.isValidSeed`（长度 1~32 + 白名单字符集）在 `handleSeedInput` 与 `SessionManager.start` 双重校验。
- `handleSeedInput` 经 `runTask` 回主线程执行（同步 openMenu 在普通任务中合法），玩家下线/`states` 缺失/已通过命令开局均有守卫。
- `SessionManager.start` 的种子兜底校验与 `putIfAbsent` 开局重入防护保持不变。
