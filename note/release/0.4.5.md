# Balatro v0.4.5 — 小丑销毁 flags 残留修复（REF 对齐）+ 商店金钱饱和防护

> 基线：Minecraft 1.21.11 / Paper API（Papo 服务端）。本轮主题为「引擎数值边界 +
> 消耗品/商店边界路径」：无尽模式高底注的 long/double 溢出路径全量复核（既有饱和防护
> 验证到位，见下），并对消耗品/补充包/商店交易逐路径对照 REF engine.js，
> 发现并修复 4 项缺陷。完全向后兼容（普通局行为不变；种子复现不受影响——
> 修复均不消耗随机流）。

## 修复清单

| # | 问题 | 修复 | 严重性 |
|---|---|---|---|
| 1 | **destroyJoker 移植遗漏**（对照 REF engine.js:1971-1976）：REF 在销毁函数内置 `grosDead` 置位 + `computeFlags`，Java 移植二者皆无——①仪式匕首/癫狂吞掉格罗米歇尔**不解锁卡文迪什**（grosDead 仅在自毁调用点手动置位，永久阻塞 cavendish 生成）；②被毁小丑的 flags（手牌上限/四指/飞溅/信用等）残留至下次重算 | `RunState.destroyJoker` 内置 grosDead 置位 + `recomputeFlags`；BasicJoker 格罗米歇尔自毁调用点的冗余置位去除 | REF 移植遗漏（功能不符 + 陈旧状态） |
| 2 | **hex 幻灵牌销毁小丑后 flags 残留**：hex 直接 `removeIf` 改写小丑列表（不经 destroyJoker/gainJoker，REF 本身亦遗漏此处的 computeFlags）——商店内 hex 销毁信用卡后 `credit` 标志仍生效，**无信用卡也能欠债消费**；四指/手牌上限等标志同样在残余阶段内错误生效 | `Consumables.use` 成功后统一 `recomputeFlags`（不消耗随机流） | 逻辑漏洞（可轻率利用的陈旧状态） |
| 3 | **canAfford long 溢出**：无尽模式金钱可饱和至 `Long.MAX_VALUE`，`money + credit` 直接相加环绕成负数——买得起误判为买不起（失败方向安全但语义错误） | 改用 `RunState.satAdd(money, credit)`，对齐 money 全域饱和约定 | 边界数值缺陷 |
| 4 | （随 #1 一并修复）BasicJoker 格罗米歇尔自毁调用点 `grosDead = true` 冗余 | 删除（destroyJoker 统一置位，行为不变） | 代码冗余 |

## 本轮复核确认安全的路径（留档）

- **计分尾部**：`chipsR/multR → Math.round` 对超 long double 自动钳制；`roundScore` 经 `satAdd` 累加（既有 c8e27be 防护验证到位）；等离子平衡为 double 均值，无环绕。
- **目标分**：`blindBase` 无尽表超 long 项钳制 `Long.MAX_VALUE`；`blindTarget` 的绿/紫注指数放大为 double 运算，`Math.round` 对 Infinity 饱和——无尽 16+ 底注不环绕。
- **回合经济**：利息 `min(interestCap, money/5 * rate)`（cap ≤ 20）；奖励/剩余出牌/绿牌组均为小整数；小丑 payout 经 `satAdd`；`reward *= rewardMult`（≤3）无溢出。
- **REF 逐项对照确认一致**：useSeq 失败亦递增（流名参数求值时机一致）、emperor 抽到自身消耗名额（`continue` 一致）、strength 对 A 不生效、ouija/ectoplasm 手牌上限无下限（REF 语义）、hieroglyph/petroglyph 仅「底注 -1」（REF data.js 描述一致，无手牌/弃牌惩罚项）、priestess/emperor 满槽先抽后弃（一致）。
- **会话层相位门控**：buy/buybag/buyvoucher/reroll 均经 `GameSession` 检查 `phase==SHOP`，引擎层无绕过入口；Packs.open 嵌套开包的 `packReturn` 保持链正确。
- **出售/使用入口**：`sellJoker/sellConsumable` 无相位限制（对齐真版任意时刻可售）；`use` 引擎内强制 ROUND/SHOP 相位 + 目标卡 id 必须属于当前手牌 + 去重，伪造 id 不可越权。
