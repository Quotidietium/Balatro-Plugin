# Balatro v0.4.60 — R223：默认奖励管线补全（#79）+ 满载压测实证

> 基线：Minecraft 1.21.11 / Paper API（Papo 服务端）。实机审计第三轮（R223）。

## 改动（#79 表述-实现不符修复，src/main 变更）

**问题**：项目计划书 §7.2（已确认设计）与实机清单 #14 承诺「RewardService 默认转发到
EconomyService（可关闭）」「奖励到账（余额核对）」，但实现中默认奖励为 `NoOpReward`
空操作——装 Vault 后仅接线经济（`已接入 Vault 经济`日志）而**从不发放任何奖励**，
文档承诺落空。R223 实机验证（Vault 1.7.3 + EssentialsX 2.22.0 真服）实锤：清盲后
`/balance` 余额纹丝不动。

**修复**：

- 新增 `service/EconomyReward`（默认奖励策略）：过关节点经 `EconomyService` 发放；
  经济实现经 `Supplier` 现取（运行期 `setEconomy` 替换即时生效）；金额 ≤0 的档位
  不发（0=关闭该档，负数防配置笔误倒扣）；失败局不发。
- 新增 `config.yml`（首个插件配置）+ 启用期 `saveDefaultConfig`+`copyDefaults`
  热补齐：`reward.economy.{enabled,blind,ante,win}`，默认 `true/1/10/100`；
  `enabled=false` 回落 `NoOpReward`。
- `BalatroPlugin.onEnable` 接线：读配置装配 `EconomyReward`（无 Vault 时 EconomyService
  为 NoOp，deposit 无副作用——行为与旧版等同）。
- 文档同步：`RewardService`/`NoOpReward` javadoc、README 可选集成段。

## 兼容性

- 默认行为变更：装 Vault+经济插件的服务器将开始按配置发放过关奖励
  （盲注 $1/底注 $10/通关 $100）——这是文档既有承诺；不希望发放的服务器设
  `reward.economy.enabled: false`（或各档 0）。
- 未装 Vault 的服务器行为与 0.4.59 完全一致（经济为 NoOp）。
- API 无变更（接口未动；默认实现替换属设计内行为）。
