# Balatro v0.4.3 — 服务层一致性 + 排行榜查询节流

> 基线：Minecraft 1.21.11 / Paper API（Papo 服务端）。在 0.4.2 基础上修复服务替换
> 一致性缺陷与排行榜只读命令的宏刷 DoS 面。无引擎/渲染行为变化，完全向后兼容。

## 修复清单

| # | 问题 | 修复 | 严重性 |
|---|---|---|---|
| 1 | 第三方按 API.md 只调用 `services().setStats(自定义实现)` 替换统计后，`MemoryLeaderboard` 仍持有**旧统计源**（final 字段），新记录不再反映到排名——排行榜静默停止更新（既有测试都需手动重建排行榜绕过） | `MemoryLeaderboard` 增加 `setStats`（stats 去 final），`Services.setStats` 检测 `MemoryLeaderboard` 即自动重绑（与 0.3.9 `setWinCounter` 同步注入同一约定）；新增回归测试 `setStatsRebindsMemoryLeaderboardSource` | 第三方集成逻辑缺陷（与 API 文档表述不符） |
| 2 | `/balatro top` 无节流：聚合排行榜每次全量遍历统计记录（上限 1 万条，含复制/HashMap 聚合/排序），Bukkit 命令无原生限流——篡改客户端可宏刷这条只读命令，让主线程反复做全量聚合排序 | 每玩家 1s 节流；节流表惰性清扫（>60s 失效、超 128 条触发清扫），长期运行玩家流转下有界 | 高负载稳定性（DoS 面） |

## 本轮复核确认安全的点（服务层 / API 事件层）

- **FileStats**：流式有界加载（启动无内存尖峰）+ 追加写入 + 每 1 万次追加原子压缩（临时文件 + move，崩溃不留半文件）；decode 严格 7 段 + 种子长度/控制字符拦截脏行；record/all 全 synchronized。
- **FileWinCounter**：整文件原子重写；脏行跳过；IO 失败记日志不崩溃。
- **MemoryStats/MemoryLeaderboard**：有界（1 万条）；排序 comparator 各段独立（无链式 reversed 反转陷阱）；winCounter 未注入时 winCount=0 降级正常。
- **VaultEconomy**：四方法全解析成功才标记可用；反射调用全 try/catch；UUID 版 `getOfflinePlayer` 无网络阻塞。
- **API 事件**：5 事件标准 HandlerList 模式，主线程同步发出；RunStart 可取消语义正确；RunSummary/PlayerStat 为不可变 record。
- **事件时序**：`GameSession.play` 仅在 `r.ok` 时发 HandScore；失败局 `endIfCurrent` 防误杀 RunEnd 监听器重开的新局。
