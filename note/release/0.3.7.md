# Balatro v0.3.7 — /balatro 简要帮助更新（覆盖全部命令）

> 0.3.6 的帮助文本补全版。基线：Minecraft 1.21.11 / Paper API（Papo 服务端）。

## 背景

直接输入 `/balatro`（无参数 / 未知子命令）时调用的 `BalatroCommand.sendHelp` 自 0.1.0
以来基本未动，仍停留在 0.1.0 的 6~13 条命令清单，**遗漏了 0.2.0 起加入的全部
商店/消耗品/补充包/出售/盲注选择/排行榜命令**，与实际可用命令长期脱节。

## 改动

### 1. `sendHelp` 重写为按阶段分组的全命令概览

- 原：扁平 13 行，仅覆盖 0.1.0 命令（play/playcard/disc/status/endless/shop/buy/
  buybag/buyvoucher/reroll/next/quit + help）。
- 现：按「通用 / 出牌回合 / 盲注选择 / 商店 / 消耗品 / 补充包 / 出售」分组，
  **覆盖全部 23 个面向玩家的命令**：补齐 `go skip cons use packs pick skipack
  sellj sellc top` 共 10 个此前缺失的命令。
- 配色沿用项目既有风格（`§6` 分组标题 / `§e` 命令 / `§7` 说明）；首行提示全息右键
  为主、命令为等价备用操作，并指向 `/balatro help` 的分页详细玩法。

### 2. `cancel` 刻意不列入帮助

`cancel` 是全息出售确认框「[取消]」可点击按钮的回执
（[RoundBoard.java](../../src/main/java/cn/quotidietium/balatro/render/RoundBoard.java)
`clickEvent(runCommand("/balatro cancel"))`，见 [0.3.3.md](0.3.3.md)），仅回一句
"已取消操作。"，并非玩家会主动输入的玩法命令。列入帮助反而会误导玩家以为能手动
取消某个状态，故不列。（仍在 `SUBS` 与 switch 中保留，供按钮调用。）

### 3. `BalatroCommand` 类头注释同步

原类头 javadoc 仍写「0.1.0 子命令：play | quit | status | playcard | disc | endless」，
已更新为准确的全命令分组概览。

## 测试

- 现有测试不约束 `sendHelp` 内容（`BalatroHelpCommandTest` 测单命令详情查找、
  `BalatroHelpPaginationTest` 测分页帮助行数上限），本次纯文本改动不影响它们。
- `./gradlew test` 通过（测试数同 0.3.6）。

## 构建

`./gradlew build` → `build/libs/balatro-0.3.7.jar`（JDK 21，paper-api 1.21.11）。

## 兼容性

- 同 0.3.6：paper-api 1.21.11（`compileOnly`），无 hard-depend，Vault 为 softdepend。
- 开发者 API 无变更；仅玩家可见的聊天帮助文本更新。
