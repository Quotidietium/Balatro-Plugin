# Balatro v0.4.7 — balatro.play 权限实施 + 事件桥/服务调用全量异常隔离

> 基线：Minecraft 1.21.11 / Paper API（Papo 服务端）。本轮主题为「命令层参数解析与
> 权限边界 + API 事件第三方滥用面」：全量复查命令分发/参数解析/Tab 补全/权限声明，
> 以及 fire* 事件桥与可替换服务（Reward/Stats/Leaderboard/WinCounter）的调用隔离，
> 发现并修复 6 项缺陷。向后兼容：默认配置（balatro.play 默认 true）行为不变；
> 引擎与种子复现不受影响。

## 修复清单

| # | 问题 | 修复 | 严重性 |
|---|---|---|---|
| 1 | **balatro.play 权限未实施**：plugin.yml 声明了权限（默认 true）但命令层与 Tab 补全从不检查——服务器经权限插件撤销后无法拦截，节点形同虚设（README「权限」节承诺的语义不成立） | `onCommand`/`onTabComplete` 实施检查；无权限者命令被拒、补全为空（不暴露命令结构）。默认 true 下行为不变 | 权限边界缺失 |
| 2 | **fireRunEnd 监听器异常吃掉统计落盘**：`callEvent` 同步执行监听器，第三方 `BalatroRunEndEvent` 监听器抛异常沿栈上抛，`finishRun` 在其后的 `reward.onRunEnd`/`stats.record`/`winCounter.increment` 全部跳过——一局结果不落盘 | 5 个 fire* 事件桥统一 try/catch：记日志、绝不向游戏流程传播；RunStart 监听器异常按「未取消」继续 | 数据操作缺陷（第三方触发） |
| 3 | **可替换服务异常级联**：RewardService/StatsService/WinCounter 均可被第三方替换（Services.setX），任一实现抛异常会跳过后续服务（如 reward 异常 → 统计/通关计数丢失） | GameSession 引入 `safeService` 逐项隔离，各自记日志后继续 | 数据操作缺陷（第三方触发） |
| 4 | **buybag 陈旧文案**：成功消息仍写「补充包选择界面 0.2.0 后续」——补充包界面早已实现（packs/pick 命令 + 全息 PACK 视图） | 更新文案并直接列出补充包内容（与 cmdBuy 重列商店一致） | 功能与表述不符 |
| 5 | **skip 得「立即开包」标签时命令路径静默**：跳过盲注得 standard/buffoon 标签 → 引擎进入 PACK 阶段；全息路径有 board.update 自动简介，命令路径无任何提示 | cmdSkip 检测 PACK 阶段即列出补充包内容 | 用户交互逻辑缺陷 |
| 6 | **cmdTop 第三方排行榜异常击穿命令**：`topAggregated` 为可替换服务，异常经顶层兜底显示「处理命令时出错」（观感如插件自身故障） | 就地 try/catch 降级为「排行榜服务暂不可用」 | 健壮性（第三方触发） |

## 本轮复核确认安全的路径（留档）

- **参数解析**：parseOne/parseIndices 全部 try+越界拦截；use/sellj 的「期望身份」校验（0.4.2 引入）完好；cmdPlay 的参数自动识别沿用既有文档化歧义（单字符数字种子被赌注识别遮蔽，GUI 不受影响）。
- **Tab 补全**：filter 前缀小写归一；help 页码范围由注册表生成；play 仅补牌组名+赌注数字（既有设计）。
- **权限声明**：`balatro.admin` 目前无任何管理子命令可门控（声明保留给后续管理操作），本轮仅留档说明，不强行挂载。
- **onEnable/onDisable**：启动清扫残留牌桌实体（全世界 balatro_board tag）+ 关停先关菜单再收会话，顺序正确。
- **cmdTop 性能**：1s/人节流 + 惰性清扫有界；`getOfflinePlayer(uuid).getName()` 走内存 usercache（无磁盘 IO），null 回退 UUID 前 8 位。
