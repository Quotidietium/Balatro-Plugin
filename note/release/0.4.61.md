# Balatro v0.4.61 — R225：目标类消耗品全息使用链路修复

> 基线：Minecraft 1.21.11 / Paper API（Papo 服务端）。实机缺陷 #80（用户实玩报告）。

## 问题（#80 目标丢失）

用户实玩报告：右键选中 1~N 张手牌后，使用道具（如幻灵「光环」制作镭射卡牌）提示
未选中卡牌。根因：`RoundBoard.sendUseConfirm` 生成的「确认使用」按钮命令只有
`/balatro use <序号> <kind:key>`，**不携带任何目标**——21 种目标类消耗品（塔罗增强
9 种/改写 3 种/蜡封 4 种/光环/隐匿/星球改花色 4 种/死神）在全息两步流上事实上不可用，
只能退回手打命令。帮助文案甚至明载这一缺口（原 use 帮助：「全息右键为『无目标使用』，
需目标时请用命令」）。

## 修复（src/main 变更，v0.4.61）

1. **引擎**：`Consumables` 新增单源使用需求元数据 `useInfo(key)`（record
   `UseInfo(minTargets, maxTargets, roundOnly)`），替换原 `NEED_ROUND_TARGET` 集合
   （needsTargets 键集合逐字相同，非回合预检行为不变；消除双源维护面）。
2. **命令层**：`/balatro use` 支持第三种参数形态 `@id1,id2`（`UseTargets` 纯解析器，
   零 Bukkit 可单测）：全息确认按钮携带**确认时刻选中牌的卡 id 快照**（手牌从左到右
   序）。卡 id 不随列表/手牌变化漂移——命令层校验快照 id 仍全部在手牌，缺一即取消
   （目标侧 TOCTOU，R52 序号错位防线的同族收口）。手动手牌序号路径向后兼容不变；
   @ 令牌与序号混用拒绝。
3. **板端（RoundBoard）**：
   - `sendUseConfirm`：选中数满足需求时确认命令附 `@ids`（一键生效）；提示行预告
     「需选中 N 张手牌（当前 M 张）」；`infoFor` 消耗品简介同步标注需求。
   - `sendSellConsumableConfirm`（商店）：无目标且不限回合的消耗品（星球/非目标
     塔罗/部分幻灵）补「[确认使用]」按钮——引擎本就允许商店使用（Phase 检查
     ROUND/SHOP），此前板面无入口。
   - `playSelected`/`discardSelected` 统一按手牌从左到右序传 id（原 HashSet 迭代序
     非确定：弃牌紫蜡封流序、死神「左变右」目标次序随哈希布局漂移）。

## 测试（+6，共 536 全过）

- `ConsumablesUseInfoTest`：①needsTargets 键集合=原 21 键等价锁；②**行为边界锁**
  ——21 目标 key × N∈[0,4] 实际调用 use()，成功⟺min≤N≤max（useInfo 表与 apply
  分支任何一侧漂移即红）；③非回合预检/分支行为等价锁。**变异验证 ×2**：变异
  apply(strength 2,false→true) 与 useInfo(death 2,2→1,2) 均红，还原全绿。
- `UseTargetsTest`：合法/次序保持 + 18 种非法形态全拒。**变异验证**：放行重复 id →红。

## 兼容性

- 手动命令 `/balatro use <序号> [手牌序号...]` 语义与文案不变；@ 令牌为板端内部
  协议（手动输入带 @ 会被明确拒绝，不产生歧义）。
- 引擎行为零变化：预检键集合等价、流消耗点未动、useSeq 顺序不变（种子复现不受影响，
  536 测试含全部黄金用例通过）。
- API 无变更。
