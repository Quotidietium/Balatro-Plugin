# Balatro v0.3.5 — 修复出牌耗尽不结束 + 结束发送本局统计

> 0.3.4 的逻辑修复版。基线：Minecraft 1.21.11 / Paper API（Papo 服务端）。

## 修复 / 改动

### 1. 出牌数耗尽后正确结束（实机反馈「没结束」）

**现象**：出牌数（`handsLeft`）耗尽后，玩家感觉游戏没结束——还能乱点牌桌（点了无反应）。

**根因**：引擎逻辑本就正确（`playHand` 在 `handsLeft<=0` 且未达目标分时调 `loseRun` → `phase=END`）；但全息路径的 `finishRun` **不发任何消息、不销毁牌桌**，牌桌停留在 END 阶段仍渲染并可点击（点击因非回合而无效）→ 玩家以为没结束。

**修法**：`finishRun` 在**失败**时销毁牌桌并移除会话（玩家可立刻 `/balatro play` 再来一局），并发送结束统计（见下）。

### 2. 任何结束情况都发送本局统计（实机反馈）

`finishRun` 新增 `sendRunStats`：通关或失败均在聊天框发送本局统计：

```
━━ 本局结束 ━━
通关！/ 本局失败   到达底注 X / 8
种子 SEED · 牌组 名 · 赌注 名 [· 挑战 名]
打出 N 手牌 · 持有 M 张小丑 · 剩余 $K
[通关] /balatro endless 继续无尽  /balatro quit 结束
[失败] /balatro play 再来一局
```

覆盖两条结束路径：失败（`play` 出牌耗尽）、通关（`nextRound` 击败 ante 8 Boss）。

### 3. 修复无尽模式 `won` 标记泄漏（关联隐患）

通关(ante 8)时 `state.won=true`，而 `continueEndless` 未重置 → 无尽模式中每赢一个盲注，`play()` 的 `if (state.won)` 会**重复触发** `finishRun(true)`（重复记录通关统计/发结束事件；若叠加「结束即销毁牌桌」会直接打断无尽）。修：`continueEndless` 重置 `s.won=false`（通关的 `finishRun` 已在 `nextRound` 触发一次）。

## 测试

- `./gradlew test`：**72 测试全过**（原 70 + 新增 `GameEndTest`×2：出牌耗尽判失败、`continueEndless` 重置 won）。
