## 三、方法学资产（二期新增）

1. **交替顺序协议**：配对内也必须交替先后（bl,cur / cur,bl），消除「配对内后跑者系统性承压」偏置。
2. **产物符号校验硬门**：每轮 A/B 前校验 jar 内 class 含本轮标记符号（P10 事故：增量编译缓存损坏
   导致 jar 混入旧类，A/B 数据作废重跑——由 javap 反汇编缺方法暴露）。
3. **JFR 归因须区分稳态/预热**：小分配（32~104B）在 C2 稳态多被逃逸分析消除，JFR 采样到的
   可能只来自解释/C1 段；以「改动前后 ThreadMXBean 总量」为准，JFR 仅定位候选（P10 负结果）。
4. **小列表复用不敌 TLAB**：晋升缓冲的写屏障+缓存冷成本 > 新鲜分配；池化只对必然存活的
   大缓冲成立（P10 快照池中性、P11 商店池 +4% 回退——两次独立实验同结论）。
5. **discard 套件顺序伪影**（P6 发现）在二期复现并按孤立 A/B 协议处置。

## 四、红线执行记录

1. **种子复现**：全部改动零触碰流名/调用次序/消耗次数；P11 建流改造附逐位等价论证 +
   `RngStreamPrefixTest` 守门（7 种子×12 流名×64 值 + 前缀态恒等式）。
2. **测试**：每轮 `clean build` 全过（458→460，新增 2 个守门测试）。
3. **sinkΔ**：每轮 9 场景独立 JVM 逐位一致（含收官三对全场景）。
4. **API**：既有公开签名零变化；新增仅 `RunState.acquireJokerSnap/releaseJokerBuffer`
   两个引擎协作方法（严格配对契约，Javadoc 注明）。

## 五、剩余优化面（判定：结构性收官）

| 项 | 判定 |
|---|---|
| Card×52/局 | 必要可变状态，跨局池化违反稳定性红线 |
| msg/事件字符串 | 功能性输出（GUI 消费），保留 |
| Mods/JokerInstance/usedPlanets 等 public final 容器壳 | API 冻结 |
| 快照/小列表池化 | 两轮实验证明中性或负收益（EA+TLAB 已最优） |
| 渲染层深层改造 | 无实机不可验证（沿袭一期 P7 结论，待实机清单第 17 项 TPS 数据） |
