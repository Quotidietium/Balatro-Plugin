# P2 性能优化报告 — 随机流层（Rng / StreamSource）

> 日期：2026-08-16 · 分支：`perf/plugin-performance` · 版本：v0.4.39 → **v0.4.40**
> 基线：P1 提交（3d20894，优化前引擎）· 测量协议：**best-of-3 交错 A/B**（见下）

## 优化点

| # | 位置 | 改动 | 依据 |
|---|---|---|---|
| 1 | `StreamSource.stream()` | `computeIfAbsent(name, lambda)` → get/缺省建/put | 原实现**每次调用新分配**一个捕获 `runSeed` 的 lambda 实例（基准实测 16 B/op，每玩家每次 prob/rngInt/取流都走）；命中路径改为零分配。单玩家单线程，无并发语义变化 |
| 2 | `Rng.Stream.range/pick/shuffle` | `(int) Math.floor(x)` → `(int) x` | x≥0 且非 NaN 时截断≡向下取整，逐位等价；next()∈[0,1) 保证前提。每次流消耗省一次 Math.floor 调用 |
| 3 | `Rng.seedHash` | 去掉冗余 `String.valueOf(s)` | 入参恒为非空 String（调用点均为字符串拼接），无行为变化 |
| 4 | `Rng.randomSeedString` | 字母表提为静态常量 | 免每次调用重建 String（每局一次，卫生性改动） |

**红线核对**：随机流的调用顺序、流名、消耗次数零变化（floor 截断逐位等价论证见上）；
458 测试全过（含 54 黄金种子复现 + Rng 1248 逐值断言）。

## 测量方法学（v2，本轮确立）

- 单次运行噪声实测：同二进制两次运行 playHand 中位数漂移可达 ~36%（共享机器后台负载
  + GC 异步噪声 + JIT 布局抽签；噪声只会使时间**变大**）。
- 因此正式结论一律：**同代码连跑 3 次 JVM + 与对照版本交错执行（A B A B A B），
  各场景取 3 次中位数的最小值（best-of-3）**。基线在 P1 提交的 worktree 上测得，与当前代码交错。
- 分配字节/op 为 TLAB 估算（±1 个 TLAB 步长的量化误差，1314↔1497 即此类抖动），看趋势。

## 结论

- 直接目标命中：命名流查找 2× 提速且零分配；流消耗端（floor 截断）惠及全部重流场景。
- 整局吞吐 +13.6%（每局 2.67ms → 2.31ms）；回合循环 +18.2%。
- handEval/discard 的负 delta 属未触碰路径上的环境噪声（交错协议下仍 ±10%），
  后续轮次的改善以 >15% 或分配量级下降为准绳。
