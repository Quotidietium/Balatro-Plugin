# P14 — 消耗品/补充包路径：一次性流分段折叠 + 快照池化补点

> 日期：2026-08-16 · 分支：`perf/plugin-performance` · 基线：v0.4.51（0e18c0e + 场景 cherry-pick）
> 红线：安全性/稳定性/兼容性（种子复现、API 契约、473 测试）——全程零破坏
> 新增测量面：`useConsumable` / `packOpen` 两场景（P4 先例允许加场景，既有 9 场景锁定不动）

## 一、动机

第三期前两轮后，消耗品/补充包路径无基准覆盖。新增场景并剖析发现三类问题：

1. **一次性流名的双重浪费**：`"use:"+key+":"+roundCount+":"+seq` 与
   `"pack"+roundCount+":"+key+":"+seq` 内嵌**严格递增序号**（useSeq/packSeq）——名字永不复现，
   却每次走「String 拼接物化 + HashMap 插入（Node+扩容）」，且长局下（无尽模式重度用牌）
   缓存 Map **无界增长**。
2. **P10 池化快照遗漏点**：Consumables.use 的 onUseTarot/onUsePlanet 分发与 Packs 的
   onPackOpen/onPackSkip 分发共 4 处仍是 `new ArrayList<>(s.jokers)`（P10 只覆盖了 Engine）。
3. **targets() 查重**：每次使用消耗品 `new HashSet<>(targetIds)`（≤3 个 id 的装箱分配，
   P4 同款问题）。

## 二、改动（全部严格胜出：以更少工作替代，无额外遍历）

1. **分段折叠建流（零字符串物化/零缓存插入）**：FNV-1a 左到右可分段——
   `Rng.streamUse/streamPack(prefix, ...)` 直接从前缀态折叠 `"use:"+key+':'+rc+':'+seq`
   等分段（int 段折叠其十进制字符，负数含 '-'，MIN_VALUE 用 long 幅度）。
   `RunState.streamUse(key)/streamPack(key)` 封装序号自增。与旧
   `stream(拼接名)` **逐位等价**（守门测试锁定语义矩阵 ×64 值）。
   - 开发中事故与修复：foldInt 首版 `(int)(m/pow)%10` 在商 ≥2^31 时溢出为负
     （MIN_VALUE 末位折叠出 `'('`）——**先取模再转型**修复；守门测试含 MIN_VALUE/负数边界。
2. **4 处快照点池化**（P10 深度池，try/finally 严格配对）。
3. **targets 查重两两比较**（`Integer.intValue()` 比较，去装箱分配）。
4. 流名全量清点守卫（R106）扩展分段入口：`.streamUse(`/`.streamPack(` 调用点同样过白名单审计。

## 三、守门与行为等价

- `RngSegmentedStreamTest` 4 用例：streamUse/streamPack 语义矩阵（种子×key×回合×序号×16 值）
  对 `makeStream(拼接名)` 逐位断言；foldInt 对 `Integer.toString` 折叠逐位（含 MIN_VALUE）；
  RunState 级孪生对照（含序号递增副作用）。
- 473 测试全过（+4）；黄金测试锁定全链路对 REF 复现。
- 场景 sinkΔ 改前改后**完全一致**（useConsumable=240096 / packOpen=480022）——行为等价
  在新场景上直接验证。

## 五、结论

**正收益轮**：消耗品使用 **1.372×（分配 −49%）**、补充包 **1.832×（−24%）**——
一次性流的「拼接物化+缓存插入」被分段折叠替代（顺带消除长局缓存 Map 无界增长）、
4 处快照池化补点、targets 查重去装箱。既有 9 场景分配逐位持平（改动不在其路径），
时间面中性。副产品方法学：**int 段折叠须先取模再转型**（商 ≥2^31 的 (int) 溢出事故，
MIN_VALUE 末位折叠出 `'('`——守门测试边界用例锁定）。
