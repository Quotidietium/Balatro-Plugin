# P4 性能优化报告 — 计分管线（playHand/discard）+ 枚举列表缓存

> 日期：2026-08-16 · 分支：`perf/plugin-performance` · 版本：v0.4.41 → **v0.4.42**
> 基线：P1 提交（优化前引擎）· 测量协议：best-of-3 交错 A/B（数值为**累计**效果，含 P2/P3）

## 优化点

| # | 位置 | 改动 | 说明 |
|---|---|---|---|
| 1 | `Data`（新增） | 枚举缓存列表 `HAND_TYPES/ENHANCEMENTS/SEALS/TAROTS/PLANETS/SPECTRALS` | `values()` 每次克隆内部数组、调用点再 `List.of(...)` 包一层——商店/补充包/紫蜡封/消耗品/轨道标签等 **12 处热路径**逐次分配，全部改用缓存（不可变，顺序=声明序） |
| 2 | `Engine.playHand` | 查重/包含/移除改 `int[]` + 两两比较 | 原 `new HashSet<>(cardIds)` + `List<Integer>.contains(c.id())` 每次**装箱**（card id 超出 Integer 缓存区间逐个分配）；`removeIf` 谓词 lambda 一并消除。出牌保持「手牌顺序结算」（原 indexOf 稳定排序 ⇔ 单趟手牌选取，等价论证） |
| 3 | `Engine.discard` | 同上 | **cards 保持 cardIds 顺序**（原实现语义）——紫蜡封按此顺序消耗流、onDiscard 钩子看到此顺序；中途曾误改为手牌顺序，自查发现后回退（种子复现敏感点） |
| 4 | `Card.hashCode` | `Objects.hash(id)` → `return id` | 原实现每次调用分配 varargs `Object[]` |

## 行为保持证据（红线）

1. `./gradlew build`：458 测试全过（黄金种子复现 + 混沌 fuzz 全量）。
2. **干净 JVM 校验和对照**：7 个确定性场景（handEval/playHand/discard/roundCycle/shopGen/createRun/fullRun）
   在优化前/后各跑一个独立 JVM，全部 `sinkΔ` **逐位一致**
   （6818688 / 335373750 / 240000 / 1479600 / 270000 / 3744000 / 5719）——
   与测试互补的黑洞校验和证据。

计分管线的装箱/谓词/枚举克隆全部消除；整局吞吐累计 **2.835×**（2.35ms → 0.83ms/局），

**构局与回合/商店生命周期**（createRun 6.6KB/次、startRound 快照、genShop 商品对象、
computeFlags HashMap 重建）——即 P5 的目标面。
