# P13 — Card 位打包紧凑化（48→32B/张）

> 日期：2026-08-16 · 分支：`perf/plugin-performance` · 基线：v0.4.50（54d18ed）
> 红线：安全性/稳定性/兼容性（种子复现、API 契约、469 测试）——全程零破坏
> 状态：**结构性正收益轮收官**（分配 −832B/局确定性、时间中性、行为 sink 级等价）

## 一、动机

P12 的 JFR 归因显示 createRun 剩余分配 4,686 B/op 中 **52 张 Card ≈ 2.5KB（~55%）为最大项**
（原 10 字段布局：3 枚举引用 + 2 int + long + 3 boolean ≈ 48B/张）。Card 全部字段私有、
访问一律经 getter/setter——位打包可完全封装，公开 API 零变化（用户已授权结构性重写）。

## 二、设计

```java
private final int id;
private int bits;        // rank[0,6) | suit+1[6,9) | enh ord+1[9,13) | ed ord+1[13,16) | seal ord+1[16,19) | debuff|facedown|broken
private long chipBonus;
```

- 对象 48→**32B**（−33%）；一副 52 张省 **832B/局**；全牌遍历（洗牌/整理/全清 debuff）缓存密度提升。
- 域约定（与游戏域一致）：rank ∈ [0,63]、suit ∈ [-1,6]、枚举或 null；游戏内写入点全在
  rank 0..14 / suit -1..3。越界按位截断（Javadoc 声明）。
- 枚举解码走静态 `values()` 缓存数组（类加载一次，无逐次分配）。
- 守门：`CardPackingTest` 6 用例（域 roundtrip / 位独立性 / 石头转换 / 快速谓词恒等 /
  域内变异稳定 / toString）+ 既有 54 黄金与 CardStateTransitionTest 等全量行为锁定。

## 三、第一轮 A/B（best-of-3 交替顺序，全场景）

分配（确定性，全部符合 52×16B 摊销预期）：

| scenario | 分配 B/op | 时间 |
|---|---|---|
| createRun | 4,686 → **3,854**（−17.8%） | **1.350×**（分离：cur 565/641/813 < bl 763/774/905） |
| shopGen | 7,914 → 7,081（−10.5%） | **1.290×** |
| playHand | 9,845 → 9,034（−8.2%） | **0.796×（回归）**（cur 6784/6789/6970 vs bl 5404/6632/5401） |
| handEval | 231 → 231 | **0.931×（回归）**（cur 101/117/119 vs bl 97/94/110，轻分离） |
| discard | 477 → 445 | 1.028× |
| roundCycle | −826B | 0.960× |
| fullRun | −773B | 1.093× |

**回归归因**：`enh() == X` 从指针比较变为 shift+mask+**解码数组取**+比较——热循环
（HandEval 过滤 × 每张、scoreOneCard × 每计分牌 × 5 分支、held 环、isSuit 适配）
逐次放大；playHand 另受 5 小丑钩子 × 逐卡 × isSuit 调用链放大。

## 四、修正：热路径快速谓词

新增 `isEnh/isEdition/isSeal(枚举)` —— 直接比较位段编码（shift+mask+int 比，**无解码数组**），
与 `getter() == e` 恒等（编码即 ordinal+1 单射；守门测试锁定全组合恒等 + null 态全 false）。
内部热点调用点切换 19 处：HandEval（suited 过滤/suitMatch/石头计分）、Engine
（scoreOneCard 全部分支/retrigger 红蜡封/held 钢铁/玻璃破碎/钩子弃紫蜡封/endRound 金蓝蜡封/
drawOne Boss 花色）、RunState.isSuit。isStone() 改单次位段比较。
冷路径（渲染/消耗品/小丑钩子内的 enh() 读）保留解码——频度低不值得改写。

## 六、结论

**结构性正收益轮**：Card 48→32B/张，每局构局分配 −832B（createRun −17.8%），
全部场景分配确定性下降；时间中性（无分离回归，首轮解码回归经快速谓词修复并由
聚焦+终态双重复测证实消除）。位打包的枚举比较成本必须用位段谓词对冲——
「打包数据结构 + 配套热路径谓词」为本轮可复用模式。
