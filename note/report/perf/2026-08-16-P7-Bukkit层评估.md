# P7 性能优化报告 — Bukkit 渲染/交互层评估

> 日期：2026-08-16 · 分支：`perf/plugin-performance` · 版本：v0.4.44 → **v0.4.45**
> 性质：评估轮（红线约束：无实机环境，只落地可验证/显然安全的优化，其余记载转实机清单）

## 评估结论：渲染层架构已是最优形态

`RoundBoard` / `BoardListener` 的既有设计（R25/R56 审计定形）没有发现结构性浪费：

| 维度 | 现状 | 评估 |
|---|---|---|
| 实体生命周期 | 实体池（slot 复用）+ 原地改写（不 clear+respawn） | 已是最优，无重建churn |
| 刷新模型 | **事件驱动**（每次玩家动作一次 update），无周期 tick | 零空闲开销 |
| 点击命中 | Bukkit `Interaction` 实体**原生命中盒** + `PlayerInteractEntityEvent` | 零自研射线开销（优于计划书时代的 HoloRaycast 方案） |
| 点击频率 | 150ms 每玩家节流 | 上限 ~7 次/秒/玩家，天然限流 |
| 自愈/迁移 | 半死检测才整体重建 | 仅异常路径付出重建成本 |

**引擎侧优化已自动继承到渲染路径**：
- `evalText` 每次选中变化调 `HandEval.evaluate` → P3 的 **3.66×**；
- `cardFace` 每张牌调 `Data.Suit.byIndex` → P6 的 **O(n)→O(1)**；
- `evalText` 查 `handLevels` → P5 的 EnumMap 数组寻址。

## 落地的优化（1 项，可证明安全）

`RoundBoard.setScale`：唯一调用点传常量 `CARD_TEXT_SCALE`——每次更新每张牌
`new Transformation + 2×Vector3f`（约 15 个小对象/次更新）改为**静态单例缓存**。
`setTransformation` 读取数值写入实体元数据、不持有该实例，共享安全；渲染结果逐值相同。

## 有意不做（转实机验证后决策）

更深层的渲染改造（Component 聚合、scoreboard tag 批处理、视距裁剪参数等）在**无实机
环境的前提下不可验证**，违反稳定性红线——全部保持现状，挂到既有实机清单第 17 项
（TPS 基线采样）之后按数据决策。

## 兼容性

458 测试全过；渲染输出逐值相同。0.4.x 直接替换 jar。
