# P11 — 流创建与构局残留（v0.4.49，二期收官轮）

> 日期：2026-08-16 · 分支 `perf/plugin-performance`（第二期第 4 轮）
> 基线：v0.4.48（37acb45）· 红线：行为零变化（460 测试 + sinkΔ）

## 一、热点定位（P10 后 JFR 复采样）

| 来源 | 归因 |
|---|---|
| `Card@makeCard`（~17%） | 构局必要状态，不可池化（红线） |
| `Rng.makeStream` byte[]/String（~1.5%） | 每个新流 `runSeed+"::"+name` 拼接（每局 15~30 次） |
| `Data$HandType.values`（~1%） | `RunState.<init>` 每次遍历 values()（枚举每次新数组） |
| `Mods`/`JokerInstance` HashMap 壳（~3.5%） | public final 字段，API 红线不可惰性化 |
| `Shop.makeJokerItem` Object[]（~6%） | 池按桶精确预置后的必要容量（P9 已优化 3×） |

## 二、改动（保留）

1. **流创建零字符串化**：`Rng.prefixHash(runSeed)` 折叠 `runSeed+"::"` 前缀态（每局一次），
   `streamFrom(prefix, name)` 增量折叠流名——FNV-1a 左到右折叠可分段，与
   `makeStream` 拼接哈希**逐位等价**；`StreamSource` 未命中路径改走此前缀（公开
   `makeStream` 原样保留）。**新增 `RngStreamPrefixTest`**：7 种子 × 12 流名 × 64 值
   逐位断言 + 前缀态恒等式，作为种子复现红线的守门测试。
2. `RunState.<init>`：遍历共享 `Data.HAND_TYPES`（List.of 缓存）替代 `values()`。
3. `StreamSource.streams` 预置容量 32（每局流名随回合持续增长：shuffle/shopgen 后缀）。

## 三、实验与回退（负结果，与 P10 同源教训）

**商店小丑池暂存**（makeJokerItem 的池改 RunState 暂存缓冲复用）：分配 −1,069B/op
（shopGen 8,113→7,044，−13.2%），但孤立 A/B 四对 min 一致 **+4.3%**（4,071 vs 3,905ns）
——晋升对象的引用写屏障 + 缓存冷成本大于 TLAB 新鲜分配。按红线（时间回归为准）**回退**，
代码处留注释存证。结论与 P10 呼应：**几十~几百字节的小列表，TLAB 分配 + 逃逸分析已近最优，
复用反而引入旧代表成本；池化只对必然存活的大缓冲（如 drawPile 52 容量）成立**。

## 四、测量（v0.4.48 → v0.4.49，交替顺序交错 A/B）

分配（逐字节稳定）：createRun 4,766→**4,686**（−80）、playHand 10,085→**9,935**（−150，
含后回退的商店池部分的净余）、roundCycle −150、discard 持平、handEval/rngNext/streamLookup
未触碰持平。时间在本会话噪声恶化段（同版本 handEval 漂移 91↔123ns）判噪声带。
