## 5. Skill 工作流设计

```markdown
## Workflow / Steps
1. 前置检查：git status 干净 + 全量测试绿。
2. 选题：从镜头库选可构造失败模式的面；零缺陷预期时计划产出类别锁/长局锁。
3. 执行镜头：按镜头方法论读码（如 key→全消费点→持有集合三段清点）。
4. 发现处理：每条发现附证据；修复走规范入口（对照写面普查清单）。
5. 回归测试：新测试变异验证后视为有效锁。
6. 收尾：稳定性审计.md 轮次章 + 细粒度 commit（fix/test/docs 分笔）+ 必要时发版。

## Constraints
- Never 跳过变异验证直接宣称锁定。
- Never 自行拍板开放决策点（呈报用户，R165 先例：开放 35 轮仍保留）。
- Always 优先类别锁（锁整类错误）而非点锁（点锁交给黄金用例）。
- Always 在性能批次合入后跑数据安全镜头五面（静态池/ThreadLocal/缓存增长/池化逃逸/门禁）。
```
