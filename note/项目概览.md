# 项目概览

## 目的

在 **Minecraft 1.21.11** 中实现 Steam 游戏 **《小丑牌》（Balatro）** 的扑克构筑 Roguelike 玩法，
产物为一个运行于 **Papo 服务端**的插件。

## 三个参考资料

| 参考 | 位置 | 角色 |
|---|---|---|
| doudizhu | `REF/doudizhu/` | **实现方式参考**：一个已有的 MC 扑克牌（斗地主）插件，提供"在 MC 里做卡牌游戏"的架构范式（渲染、交互、会话、配置、构建） |
| balatro | `REF/balatro/` | **目标玩法规则**：Balatro 的完整规则已被提取成一套纯逻辑网页（HTML+JS），含状态机、计分引擎、内容数据表、小丑钩子模型 |
| Papo | `REF/Papo/` | **目标服务端**：本项目插件运行的服务端，是 Paper 1.21.11 的性能优化 fork |

详见 [references/](references/) 下三份分析。

## 技术栈结论

| 项 | 结论 | 依据 |
|---|---|---|
| 目标游戏版本 | **Minecraft 1.21.11** | 用户需求；Papo `gradle.properties` 的 `mcVersion=1.21.11` |
| API 版本 | **Paper API 1.21.11**（`api-version: 1.21.11`） | Papo `apiVersion=1.21.11`；doudizhu 的 `plugin.yml api-version: 1.19` 兼容到 1.21.11 |
| 服务端 | **Papo**（Paper 1.21.11 fork） | 用户需求；`gradle.properties papoVersion=0.32.1` |
| Java 工具链 | **JDK 21** | Papo 固定 `release=21`；paper-api 1.21.11 要求 21 |
| API 依赖 | `io.papermc.paper:paper-api:1.21.11-R0.1-SNAPSHOT`（`compileOnly`） | Papo 即标准 Paper API，无自定义包 |

> **关键结论**：Papo **不新增任何插件 API**（无 `papo.*` 包，API 零变更是其红线）。
> 因此本项目本质上是一个**普通 Paper 1.21.11 插件**，只是跑在 Papo 服务端上。
> 唯一的 Papo 感知调用是 `io.papermc.paper.ServerBuildInfo.buildInfo().papoVersion()`
> （返回 `Optional<String>`，非 Papo 时为空），仅可用于运行时显示，不构成编译期依赖。
> 详见 [references/papo-服务端.md](references/papo-服务端.md)。

## 已确认的关键架构选择

| 项 | 决策 |
|---|---|
| 渲染方式 | **世界全息渲染**（TextDisplay/ItemDisplay + 射线交互，沿用 doudizhu） |
| 构建系统 | **Gradle Kotlin DSL**（与 Papo 一致） |
| 会话模型 | **每人独立单局**（`Map<UUID, RunState>`） |
| 范围目标 | **实现完整功能**（终极目标 = 完整 Balatro，按版本路线图渐进达成） |

> "完整功能"理解为**项目终极目标**，分版本累积达成（见 [开发规范.md](开发规范.md) §8 路线图）。

## 版本规划

- 插件版本从 **0.1.0** 起（语义化版本）；每版改动写入 `note/release/<版本号>.md`。
- 路线图：0.1.0 引擎核心+全息骨架 → 0.2.0 商店与消耗品 → 0.3.0 全Boss+标签+幻灵 → 0.4.0 全小丑 → 0.5.0 牌组/赌注/挑战+收尾（达成完整功能）。
