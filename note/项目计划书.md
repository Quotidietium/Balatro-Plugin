# 项目计划书：Balatro-Plugin

> 在 Minecraft 1.21.11（Papo 服务端）中用全息渲染实现 Steam 游戏《小丑牌》(Balatro) 的完整玩法。
> 本计划书是后续开发的总纲；要点同步记录于 [项目概览.md](项目概览.md)、[开发规范.md](开发规范.md) 与 [references/](references/)。
> 编制日期：2026-08-09。

---

## 1. 项目概述

- **目标**：Minecraft 1.21.11 插件，完整实现 Balatro（扑克构筑 Roguelike）。
- **运行环境**：Papo 服务端（Paper 1.21.11 fork，JDK 21，Gradle 9.4.1）。
- **本质**：Papo 不新增插件 API（零变更红线），故本项目是**标准 Paper 1.21.11 插件**。
- **坐标**：`groupId = cn.quotidietium.balatro`，`artifactId = balatro`，版本从 `0.1.0` 起。
- **两个参考资料**：
  - `REF/balatro` — 目标玩法规则（纯逻辑网页，逐方法移植）。
  - `REF/Papo` — 目标服务端（版本/工具链/构建环境）。

### 2.2 已确认约束

- **渲染**：世界全息（TextDisplay/ItemDisplay + 射线交互），非箱子 GUI。
- **卡牌视觉**：首版用 **TextDisplay 文字牌面**（花色符号+点数+颜色）起步，零资源包依赖；后期可升级 ItemDisplay+贴图。
- **会话**：**每人独立单局**。
- **退出**：**直接放弃本局，不存档续局**（`PlayerQuitEvent` 清理牌桌实体）。
- **随机**：全程走种子命名流，**可复现**（分享种子即同局）。
- **构建**：Gradle Kotlin DSL，JDK 21。

### 2.3 扩展需求（重点）

> **预留 API**，便于后期添加：得分排名、过关奖励、统计、经济联动、第三方插件扩展。
> 详见 §7。设计原则：接口先行、默认实现可替换、关键节点发可取消的自定义事件。

```

   ┌──────────────┐        ┌──────────────┐        ┌──────────────┐  ┌──────────────┐
   │  engine/     │        │   session/   │        │   render/    │  │  listener/   │
   │  纯逻辑(无MC) │◄──────►│ 每玩家RunState │◄──────►│ 全息渲染视图  │  │ 射线交互+节流 │
   │  可单测       │        │  生命周期管理  │        │  Matrix4f布局 │  │              │

          │                       │
          ▼                       ▼
   ┌──────────────┐        ┌──────────────────────────┐
   │  api/        │        │ command/ config/          │
   │ 事件SPI+服务接口│       │ integration/(经济/PAPI等) │
   └──────────────┘        └──────────────────────────┘
```

**依赖方向（严格）**：
- `engine/` 不依赖任何 Bukkit API（纯 POJO + JUnit）。
- `engine/` 通过 SPI 接口（`EngineListener`）向上抛"纯逻辑事件"；`session/` 负责把它翻译成 **Bukkit 自定义事件**并驱动渲染。
- `render/` `listener/` `command/` 只读写 `session` 暴露的 `RunState`，不直接改引擎内部。
- `api/` 是对外稳定面（事件 + 服务接口），第三方与未来功能都挂在这里，不改 engine/render。

## 4. 引擎层设计（balatro 移植）

### 4.1 移植对象与红线

- 逐方法翻译 `js/rng.js`、`js/data.js`、`js/engine.js`、`js/jokers.js` 四个**纯逻辑**模块。
- `js/game.js`（DOM 渲染）**丢弃**，由 `render/` 重写。
- **移植正确性红线**：各 `stream(name)`（命名随机流）的调用顺序必须与原版逐字一致，否则种子不复现。
  → 验收方式：同一种子下，本插件与原版网页的"每手抽牌/商店/小丑随机"序列完全一致（见 §4.4 黄金用例）。

### 4.2 核心数据结构

- `Card`：`final int id`(唯一)、`int rank(2..14)`、`int suit(0..3)`、可变 `Enhancement/Edition/Seal`、可变额外字段。
  → 唯一 id 必需：一张牌会被增强/改花色/复制，不能仅靠 rank+suit 标识。
- `RunState`（移植 `createRun` 的 state 对象）：phase/money/ante/jokers/consumables/vouchers/tags/deck 系列/handLevels/handsLeft…（见 [references/balatro-规则.md](references/balatro-规则.md) §4）。
- `HandType`：13 种，含基础 chips/mult 与每级成长（lchips/lmult）+ `handLevels` 升级。

### 4.3 状态机与计分

- 状态机：`blindSelect → round → shop → (pack) → 下一盲注 → end`（8 底注通关 / 无尽模式）。
- 计分：`score = (基础筹码 + 计分牌筹码 + 各加成) × (基础倍率 + 各倍率)`；等离子牌组取平均。
- 小丑钩子：`onScore/onScoreCard/onHeld/onPlayHand/onDiscard/onEndRound/onShop`，`ctx` 提供 `addChips/addMult/handIs/isSuit/isFace/rngInt/joker.extra`。
- 复制类（蓝图/头脑风暴）经 `resolveCopy` 解析实际生效实例。
- Boss/标签/挑战/牌组/赌注 的副作用在各对应流程点注入。

### 4.4 测试策略

- `engine/` 全程 JUnit 5，**零 Bukkit**。
- **黄金用例**：取若干固定种子，记录原版网页在关键节点的输出（开局手牌、商店首轮商品、若干手计分结果、通关/失败时 ante），
  作为断言基线；本插件必须复现。种子用例随版本累积，覆盖新内容。
- 单元测试覆盖：Rng（同种子同序列）、牌型判定（13 类边界）、计分（增强/版本/蜡封/小丑组合）、商店生成、补充包。

## 5. 渲染层设计（全息，首版 TextDisplay）

### 5.1 实体选型

- **首版**：全部用 `TextDisplay`（文字牌面）。卡牌 = 花色符号(♠♥♣♦)+点数+颜色(红/黑)；增强/版本/蜡封用文字角标或附加小 TextDisplay 标注。
- **预留**：`CardFace` 抽象牌面渲染，后期可换 `ItemDisplay` + 资源包 `CustomModelData`（或接 CraftEngine/ItemsAdder）而不改上层。

### 5.2 视图模型

- 每个游戏阶段一个 `HoloView` 子类：`BlindSelectView / RoundView / ShopView / PackView / EndView`。
- 视图 = 一组 Display 实体 + 布局锚点。**切换视图 = despawn 旧视图 + spawn 新视图**（或复用实体改变换/文本）。
- `RoundView` 区域：顶部状态栏(目标分/得分/出牌弃牌)、小丑区、消耗品区、出牌区、手牌区、按钮(出牌/弃牌/排序)。

### 5.3 布局配置化

- 每个 区域/视图 的锚点、间距、缩放进 `layout-*.yml`。
- 调位改 yml 即可，不重编译；支持 `reload`。

### 5.4 交互

- `PlayerInteractEvent`（主手右键）+ `HoloRaycast` 分区检测：`raycastHand`(手牌卡) / `raycastButton`(按钮) / `raycastShop`(商品) / `raycastJoker`(小丑，购买后重排序/出售)。
- 命中 → 选中/购买/使用/出售/排序；每玩家 **120ms 节流**；配 `Sound.UI_BUTTON_CLICK`（不同动作不同音调）。
- 最大交互距离 ~8 格。

### 5.5 私有可见 / 生命周期 / 性能

- **私有可见**：每玩家牌桌实体 `setVisibleByDefault(false)` + `showEntity(plugin,e)`，仅本人可见（契合"每人独立单局"，且玩家可在自己牌桌处不被他人打扰）。
- **生命周期**：`setPersistent(false)` + scoreboard tag 追踪；`onEnable` 清残留、`onDisable` shutdownAll、`PlayerQuit`/退出 即 despawn。
- **性能**：合理 `setViewRange`；视图切换及时 despawn；**差量更新**（状态变更只重渲染变化的部分，不整表重建）；限制单服并发局数可配。

## 6. 会话层设计

- 入口命令 `/balatro play [牌组] [赌注] [种子]`（Tab 补全）；在玩家附近生成专属牌桌、建 `RunState`、`showEntity` 给本人。
- `SessionManager`：`Map<UUID, RunState>`；`start/exit`。
- **退出即弃**：玩家退出命令 / `PlayerQuitEvent` / 放弃按钮 → 销毁 `RunState` + despawn 实体，不落盘。
- `EngineEventBridge`：实现 `EngineListener`，把引擎回调翻译为 Bukkit 自定义事件（§7）并触发渲染差量更新。

## 7. 预留扩展 API（重点）

> 目标：后期加"得分排名 / 过关奖励 / 统计 / 经济联动"时，**只新增实现或监听器，不改引擎与渲染**。

### 7.1 自定义事件（`api/event/`，Bukkit Event，可取消）

| 事件 | 时机 | 关键字段 | 用途 |
|---|---|---|---|
| `BalatroRunStartEvent`(可取消) | 开始一局 | player, seed, deckKey, stakeIdx, challenge | 拦截/记录开局 |
| `BalatroHandScoreEvent` | 每手计分后 | player, handType, chips, mult, score | 实时展示/分析 |
| `BalatroBlindResultEvent` | 盲注结算 | player, ante, blindType, target, score, cleared | 盲注级奖励/统计 |
| `BalatroAnteClearEvent` | 通过一个底注 | player, ante | **过关奖励**挂钩点 |
| `BalatroRunEndEvent` | 一局结束 | player, won, anteReached, finalMoney, handsPlayed, scoreSeries… | **排名入库**、结算奖励 |

- 引擎层只通过纯逻辑 `EngineListener` 上报；`EngineEventBridge` 在主线程同步发 Bukkit 事件（Bukkit API 非线程安全，且便于取消）。

### 7.2 服务接口（`api/service/`，接口 + 默认实现）

| 接口 | 职责 | 默认实现 | 未来扩展 |
|---|---|---|---|
| `EconomyService` | 金钱查/扣/加 | `NoOpEconomy`（或接 Vault，softdepend） | 接 Vault/PlayerPoints |
| `RewardService` | 盲注/底注/通关 发奖 | 默认转发到 `EconomyService`（可关闭） | 可配置奖励表（金钱/物品/命令） |
| `StatsService` | 记录每局结果 | `MemoryStats`（内存） | 持久化（SQLite/YAML） |
| `LeaderboardProvider` | 提供排名查询 | `MemoryLeaderboard`（基于 StatsService） | 接 PlaceholderAPI 暴露变量 |
| `PlaceholderProvider` | 暴露 PAPI 变量 | （集成层，softdepend PlaceholderAPI） | 排行榜/个人最佳变量 |

- 注册：通过 `BalatroPlugin` 的 `ServiceManager`（或 Bukkit `ServicesManager`）装配；`reload` 不破坏。
- 设计原则：接口稳定在 `api/`；默认实现可被配置/其他插件替换；引擎与渲染不感知这些服务（只发事件）。

### 7.3 典型落地路径（后期，不在 0.1.0）

- **得分排名**：监听 `BalatroRunEndEvent` → `StatsService.record(...)` → `LeaderboardProvider` → PlaceholderAPI 变量。
- **过关奖励**：监听 `BalatroAnteClearEvent`/`BlindResultEvent` → `RewardService.grant(...)` → `EconomyService`。
- **第三方扩展**：监听上述事件即可，无需 fork 本插件。

## 8. 配置与本地化

- **数据外置**（后期）：牌组/Boss/小丑等可配 yml（0.1.0 先内置常量，0.3+ 逐步外置）。
- **布局 yml**：首版即有（§5.3）。

## 10. 风险与对策

| 风险 | 对策 |
|---|---|
| 全息渲染 Balatro 复杂面板工作量大 | 布局配置化 + 视图分治 + 差量更新；先 RoundView 跑通再扩展 |
| 引擎移植正确性（种子复现） | 黄金用例对照原版网页逐节点断言；`engine/` 零 MC 依赖便于单测 |
| 150+ 小丑工作量 | 统一钩子框架 + 注册表；分批实现；每批配单测 |
| 实体多→性能/包量 | `setViewRange` 收敛 + 差量更新 + 限制并发局数 + 私有可见减少广播 |
| 1.21.11 API 细节 | 以 `REF/Papo/paper-api` 源码为准（本地可查），Display/Adventure API 已验证可行 |
| 扩展 API 后续易变 | `api/` 独立包、接口先行、事件携带足够字段；默认实现兜底 |
